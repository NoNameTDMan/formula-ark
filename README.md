# FORMULA / ARK — 数式航路 (Beta 0.9.0)

数式の係数、定数項、使用資源、整数制約をプレイヤーが設計し、**厳密な整数最適化**で生産計画を決める、iPhone / PC向けオフライン対応ブラウザゲームです。

## プレイ方法

- **GitHub Pages / 任意のHTTPS静的ホスト**：このフォルダのファイルをそのまま公開し、`index.html` を開いてください。
- **PCでローカル起動**：このフォルダで `python -m http.server 8000` を実行し、ブラウザで `http://localhost:8000/` を開いてください。
- **単体HTML版**：同梱の `FORMULA-ARK-standalone.html` はネット接続とWebサーバーなしで開けます。ブラウザの `file://` 制約によりPWAインストールは不可です。
- **iPhoneでインストール**：HTTPSの公開URLをSafariで開き、「共有」→「ホーム画面に追加」。サーバー不要のゲームデータ（JSON）はLocalStorageに保存されます。

## 最初の3分

1. 管制室で現在の最適解を確認。初期設定では知識を優先するため光量が少なくなるはずです。
2. 「式の設計」から「光子圧縮」を選択し、**最低稼働を3回**にして最適化計画を変更してください。
3. 1周期（4秒）後に最初の契約が達成されます。報酬を受け取り、新しい式と演算子を獲得してください。
4. 「研究・試験」で物質・電力の上限を増やし、演算子を装着しながら契約を攻略します。
5. 目的関数の重み（λ）を変えて、最適化がどのように変化するかも確認できます。

## 数理最適化の仕様（実装済み）

実行する整数計画は

```
maximize Z = L + λ D
subject to  Σ m_i x_i ≤ M
            Σ e_i x_i ≤ E
            k_i ≤ x_i ≤ u_i, x_i ∈ Z

L = Σ [ℓ_i x_i + a_i · I(x_i>0)]
D = Σ [d_i x_i + b_i · I(x_i>0)]
```

- `M`,`E`：1周期で使える物質と電力の上限
- `m_i`,`e_i`：数式 i が1回稼働するのに必要な資源
- `ℓ_i`,`d_i`：1回あたりの光量・知識の生産係数
- `a_i`,`b_i`：その式を1回以上起動すると発生する定数項
- `k_i`：プレイヤーが指定する最低稼働回数（制約）
- `u_i`：式ごとの最大稼働回数
- `λ`：知識に付ける重み（目的関数の一部）

制約は実行時に構築され、**2資源の有界整数ナップサック動的計画法**で厳密に最適化します。全式の状態を順次列挙し、各状態でより良い目的値のみを保持します。初回起動時の定数項も列挙に正確に含まれます。探索空間は有限で、実行可能な計画では全て `OPTIMAL` の結果です。`INFEASIBLE` のときは最低稼働制約が資源制限を超えています。

**補足**：このベータ版はHiGHSやMILPのWASMポートは使いません。外部依存なし・小規模問題への厳密解法を優先しました。将来より一般的なモデルへ拡張する場合にHiGHSなどのソルバを導入できます。

感度分析の `+1物質` `+1電力` は、上限を1だけ変えて再最適化した**有限差分**です（LPの双対変数ではありません）。

## ベータ版の収録内容

- 7種類の生産数式、9種類の演算子（複数所有・個別装着）
- 5種類の研究（上限・係数・スロット・稼働容量）
- 6個のメイン契約、5個の独立した最適化試験
- 9種類の実績、活動ログ、最近32周期の生産履歴
- 目的関数の重み調整、各数式の最低稼働回数、厳密最適化、制約の感度分析
- 自動セーブ、JSONエクスポート/インポート、任意のデータ初期化
- PWA対応（HTTPS配信時）、スマホ向けレスポンシブUI、低モーション配慮
- 非アクティブ時の生産最大180周期（12分）。復帰後に一括計算します。

## 技術構成

`index.html`, `styles.css`, `core.js`, `main.js`：バニラHTML/CSS/JavaScript。`sw.js`と`manifest.webmanifest`：PWA。`tests/`：Node.jsによる検証。CDNや広告、解析、外部通信はありません。ゲームデータは端末内で完結します。

ローカル保存をクリアしたり、ブラウザを削除したりすると進行が消える場合があります。重要な進行はJSONでバックアップしてください。

## 動作確認

```sh
node tests/core.test.js
node tests/balance.test.js
```

## ゲーム設計上の注意

- 研究済みの式や演算子を調整しても、必ず契約目標を満たすとは限りません。稼働下限制約と目的関数を調整してください。
- 数値を正確に扱うため、最大保存通貨を 10^15 に制限しています。巨大数の完全な任意精度実装は正式版での検討項目です。
- インクリメンタル＋構築パズルのベータ版で、オンラインランキング、BGM、演出用画像セット、周回（転生）システムは未収録です。
